# Labeloo 0.5.3 store handoff

## Release notes

- Fixes an extra blank printed page that could appear in Chrome on macOS.
- Renders only populated labels in print output while preserving each label's
  exact Avery-compatible position on US Letter paper.
- Sizes each printable page from its populated rows and columns to avoid
  platform-specific print-layout rounding at the paper boundary.
- Prevents keyboard accessibility shortcuts and other editor controls from
  leaking into printed labels or saved PDFs.
- Keeps multi-page jobs intact and continues skipping physical pages without
  label content.

## Store update summary

Printing is now more reliable in Chrome on macOS: no trailing blank page and no
editor shortcut text in labels or saved PDFs. Label positions and multi-page
jobs remain unchanged.

## Store package mapping

- Chrome: `labeloo-chrome-0.5.3.zip`
- Edge: `labeloo-edge-0.5.3.zip`
- Opera: `labeloo-opera-0.5.3.zip`

- Firefox source: `labeloo-firefox-source-0.5.3.zip`

All packages are generated by `npm run package:stores` under
`artifacts/packages/`.

## Permission and privacy summary

This update adds no permissions and changes no data collection behavior.

- `storage`: local projects, imported field mappings, preferences, optional
  opaque account session, sync metadata, and pending context-menu selections.
- `contextMenus`: user-invoked capture of selected webpage text.
- `identity`: browser-owned Wiplash.ai sign-in with a one-time PKCE code; it
  does not expose the browser profile email to Labeloo.
- Optional `https://docs.google.com/*`: requested only for a shared-link Google
  Sheet import.
- Optional `https://auth.wiplash.ai/*`: requested only when the user starts
  Wiplash.ai sign-in, private Drive selection, or project sync.
- No tabs, history, scripting, clipboard, broad website, analytics, or
  advertising permission is requested.

The canonical description, search terms, permission explanation, and
compatibility disclaimer are in `LISTING.md`. The public privacy-policy URL is
`https://labs.wiplash.ai/labeloo/privacy/`.

## Reviewer path

1. Open Labeloo with its default three populated Avery 5160 labels.
2. Select **Print labels** and confirm print preview contains one physical page.
3. Confirm the printed page contains only the three labels, with no “Jump to
   labels,” “Jump to preview,” or “Jump to editor” shortcut text.
4. Add enough populated labels for a second physical page and confirm print
   preview contains exactly two pages.

Core editing, local imports, printing, and PDF export require no account.
